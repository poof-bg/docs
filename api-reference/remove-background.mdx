---
title: Remove Background
description: "Remove the background from an image or a video"
api: "POST /remove"
---

The core endpoint for background removal. Send an image or a video; Poof detects the media type from the file content, never from the field name, the file name or the `Content-Type` of the part.

- **Images** are processed synchronously: the response is `200` with the processed image in the body, exactly as before.
- **Videos** are processed in the background: the response is `202 Accepted` with a [job](/api-reference/jobs) as JSON. Poll the job and download the result from its `result_url` when it is `completed`. See [Video](#video) below.

GIF and animated WebP files are handled by the image path, so a GIF is still rejected (`invalid_image`) and an animated WebP uses its first frame; neither is treated as a video.

Each successful image request costs 1 credit regardless of parameters; failed requests are free. Video costs 5 credits per second of source video (10 above 30 fps), charged when the job is accepted and refunded if it fails. See [Credits](#credits).

## Request

Send `multipart/form-data` with exactly one input: `file` or `url`. The other parameters are optional form fields. The same parameter names work for images and videos; each field below says how the accepted values differ.

<ParamField body="file" type="file">
  The image or video to process. Images: JPEG, PNG or WebP, up to 20 MB. Videos: MP4, MOV, WebM, M4V or MKV, up to 100 MB (use `url` for larger files). Required unless `url` is given.

  The legacy names `image_file` (a file part) and `image_file_b64` (a base64 string, with or without a `data:image/...;base64,` prefix, images only) are still accepted and behave exactly like `file`. When several inputs are sent, `file` / `image_file` wins, then `image_file_b64`, then `url`.
</ParamField>

<ParamField body="url" type="string">
  A public `https` URL to fetch the media from. Poof downloads it server-side (up to 3 redirects, 15 second timeout). Images up to 20 MB, videos up to 500 MB. URLs that resolve to private or internal addresses are rejected with `validation_error`. Required unless `file` is given.

  The legacy name `image_url` is still accepted and behaves exactly like `url`.
</ParamField>

<ParamField body="format" type="string">
  Output format. The valid values depend on the media; sending an image format for a video (or the other way round) returns `400 validation_error` listing the valid values.

  **Images** (default `png`):
  - `png` — Lossless with transparency support
  - `jpg` — Smaller file size, no transparency
  - `webp` — Best compression with transparency

  **Videos** (default `webm`):
  - `webm` — VP9 WebM, transparent with `channels=rgba`. Best for the web
  - `mov` — ProRes QuickTime, transparent with `channels=rgba`. Best for video editors
  - `mp4` — H.264 MP4, never transparent: the subject is composited on `bg_color`

  See the [video formats table](#output-formats) for codecs, alpha and audio per combination.
</ParamField>

<ParamField body="channels" type="string" default="rgba">
  Output color channels. Same values for images and videos.
  - `rgba` — Include alpha channel (transparency)
  - `rgb` — Opaque output, uses `bg_color` for background (white by default)
  - `alpha` — Grayscale alpha mask only: white foreground, black background. For video this is a grayscale matte video with no audio track
</ParamField>

<ParamField body="bg_color" type="string" default="white">
  Background colour used whenever the output has no alpha channel: `channels=rgb`, `format=jpg` and `format=mp4`. Ignored when the output is transparent or an alpha mask. Defaults to white. Accepts:
  - Hex: `#ffffff`, `#fff`
  - RGB: `rgb(255, 255, 255)`
  - Named: `white`, `black`, `green`
</ParamField>

<ParamField body="size" type="string" default="full">
  Output size preset (megapixel cap). Same presets for images and videos; for video the cap applies to every frame and `full` is additionally capped at 1080p (longest side 1920 px, aspect ratio kept). For images, ignored when `width` or `height` is set.
  - `full` — Original resolution (video: capped at 1080p)
  - `preview` — up to 0.25 megapixels
  - `medium` — up to 1.5 megapixels
  - `hd` — up to 4 megapixels
</ParamField>

<Note>
`crop`, `padding`, `crop_margin`, `width`, `height` and `fit` below are **image-only**. Sending any of them with a video returns `400 validation_error` with `details.field` naming the parameter.
</Note>

<ParamField body="crop" type="boolean | string" default="false">
  Crop the output to the subject bounds, removing empty space around the subject.
  Pass `true`/`false`, or an aspect ratio like `1:1`, `4:3`, `16:9` to crop to that ratio around the subject.
</ParamField>

<ParamField body="padding" type="string" default="10%">
  Padding around the subject when `crop` is enabled, added to **each side** as a fraction (`0.1`) or percentage (`10%`) of the subject's size on that axis. Defaults to `10%`; ignored unless `crop` is set.

  Pass one value for both axes, or two comma-separated values as `horizontal,vertical` to pad the axes differently — e.g. `10%,7.5%` produces a canvas 120% of the subject's width and 115% of its height.

| `padding`   | Result                                                        |
|-------------|---------------------------------------------------------------|
| `0`         | Tight crop to the subject                                     |
| `10%`       | Canvas is 120% of subject width and 120% of subject height    |
| `10%,7.5%`  | Canvas is 120% of subject width and 115% of subject height    |
| `5%,0`      | Horizontal padding only                                       |

  Padding is applied before any aspect-ratio expansion from `crop`. If the padded area extends beyond the original image, it is filled with transparent pixels.
</ParamField>

<ParamField body="crop_margin" type="string">
  remove.bg compatibility alias for `padding`, used only when `padding` is absent. Percentages map directly (`10%`; CSS shorthand `5% 10%` becomes `10%,5%`). Pixel values such as `10px` cannot be honoured and are ignored.
</ParamField>

<ParamField body="width" type="integer">
  Output width in pixels, `1`–`6000`. On its own, the height follows the image's aspect ratio. Together with `height`, the image is fitted into a `width` × `height` canvas according to `fit`.

  The aspect ratio is always preserved — the image is never stretched or squeezed. Images smaller than the target are upscaled unless `fit` is `scale-down`. Applied after `crop`, and overrides `size`.
</ParamField>

<ParamField body="height" type="integer">
  Output height in pixels, `1`–`6000`. On its own, the width follows the image's aspect ratio. Together with `width`, the image is fitted into a `width` × `height` canvas according to `fit`.
</ParamField>

<ParamField body="fit" type="string" default="contain">
  How to fit the image into `width`/`height`. The image is never stretched.
  - `contain` — scale the image to fit inside the canvas and centre it. The remaining area is transparent, or filled with `bg_color` (white for `jpg`).
  - `cover` — scale the image to fill the canvas and crop the overflow, keeping the subject centred.
  - `scale-down` — like `contain`, but never enlarges: an image smaller than the target keeps its native size (centred on the canvas when both dimensions are set).

  `contain` and `cover` only differ when both `width` and `height` are set.

| Parameters                              | Result                                                                 |
|-----------------------------------------|------------------------------------------------------------------------|
| `width=500`                             | 500px wide, height follows the aspect ratio                            |
| `width=500&height=500`                  | 500 × 500, image fitted inside and centred, padding transparent        |
| `width=500&height=500&fit=cover`        | 500 × 500, image fills the canvas, overflow cropped around the subject |
| `crop=true&width=500&height=500`        | Subject cropped (with `padding`), then fitted into 500 × 500           |
| `width=500&height=500&fit=scale-down`   | 500 × 500, a smaller image is centred at its native size, not enlarged |
</ParamField>

## Response

### Images

For an image the API returns `200` with the processed image directly in the response body. Check the response headers for metadata:

| Header | Description |
|--------|-------------|
| `Content-Type` | MIME type of the image (`image/png`, `image/jpeg`, `image/webp`) |
| `X-Request-ID` | Unique request ID for support inquiries |
| `X-Processing-Time-Ms` | Processing time in milliseconds |
| `X-Image-Width` | Output image width in pixels |
| `X-Image-Height` | Output image height in pixels |
| `X-Matte-Confidence` | Confidence in the alpha matte, `0`–`1`. `1` means a fully decisive mask; lower values mean the model hedged. Heuristic, not a calibrated probability |
| `X-Matte-Ambiguous-Ratio` | Fraction of pixels with alpha between 0.1 and 0.9, `0`–`1`. High values indicate large uncertain regions — useful for flagging results for manual review |

### Videos

For a video the API returns `202 Accepted` with `Content-Type: application/json` and a job object. The video is probed before it is accepted, so the response already tells you the duration, frame count and the credit charge. Poll `status_url` until `status` is `completed`, then download `result_url`. The full job object is described on [Get Job](/api-reference/jobs); the `202` always has `status: "queued"`, `progress: 0` and `result_url: null`.

## Examples

### Basic Usage

Remove background and save as PNG with transparency:

<CodeGroup>

```bash cURL
curl -X POST https://api.poof.bg/v1/remove \
  -H "x-api-key: YOUR_API_KEY" \
  -F "file=@photo.jpg" \
  -o result.png
```

```python Python
from poof import Poof

client = Poof(api_key="YOUR_API_KEY")
result = client.remove_background("photo.jpg")
result.save("result.png")
```

```typescript TypeScript
import { Poof } from '@poof-bg/js';
import fs from 'fs/promises';

const poof = new Poof({ apiKey: 'YOUR_API_KEY' });
const image = await fs.readFile('photo.jpg');
const result = await poof.removeBackground(image);
await fs.writeFile('result.png', Buffer.from(result.data));
```

</CodeGroup>

## Video

Send a video clip to the same endpoint and it is accepted with `202 Accepted` and processed in the background. The same matting model that powers image removal is run on every frame, with a motion-aware temporal stabiliser so the matte does not flicker between frames. Use it for product clips, talking-head videos, social content, overlays, and anything else that needs a transparent or solid-background video.

The flow is: submit → poll [`GET /jobs/{id}`](/api-reference/jobs) every 2 to 5 seconds until `status` is `completed` (or `failed`) → download `result_url`. `result_url` is a direct CDN link that needs no API key and stays valid for 24 hours (`expires_at`).

<Note>
The [Python](/integrations/python#video) (`poofbg` 0.3.0+) and [TypeScript](/integrations/typescript#video) (`@poof-bg/js` 1.2.0+) SDKs return a job from the same `remove_background()` / `removeBackground()` call and ship `wait_for_job` / `waitForJob` helpers; the [MCP server](/integrations/mcp) exposes `remove_video_background`. The [examples](#video-examples) below use the raw API.
</Note>

### Limits

| Limit | Value |
|---|---|
| Duration | Up to 5 minutes |
| Upload size | 100 MB via `file`, 500 MB via `url` |
| Input formats | MP4, MOV, WebM, M4V, MKV |
| Output resolution | Source resolution, capped at 1080p (longest side 1920 px, aspect ratio kept); smaller with `size` |
| Audio | Preserved, except with `channels=alpha` (no audio track) |

### Output formats

`format` picks the container and codec, `channels` picks what the pixels contain. Every combination is valid:

| `format` | `channels=rgba` | `channels=rgb` | `channels=alpha` | Audio | `Content-Type` |
|---|---|---|---|---|---|
| `webm` | VP9 `yuva420p`, transparent | VP9 `yuv420p`, subject on `bg_color` | VP9 grayscale matte | Opus (none for `alpha`) | `video/webm` |
| `mov` | ProRes 4444 `yuva444p10le`, transparent | ProRes 422 `yuv422p10le`, subject on `bg_color` | ProRes grayscale matte | AAC (none for `alpha`) | `video/quicktime` |
| `mp4` | H.264 `yuv420p`, subject on `bg_color` (MP4 has no alpha, so this equals `rgb`) | H.264 `yuv420p`, subject on `bg_color` | H.264 grayscale matte | AAC (none for `alpha`) | `video/mp4` |

- `channels=alpha` is the matte as luma: white foreground, black background. Use it with `format=mp4` for the smallest, most widely decodable matte.
- `bg_color` defaults to white. Pass `bg_color=#00ff00` for a chroma-key green screen.
- Frame rate, duration and aspect ratio are preserved. Output resolution is the source resolution capped at 1920 × 1080 (longest side 1920 px), or smaller with `size`.
- The result file is served with `Content-Disposition: attachment; filename=result.<ext>`.

### What to expect

The model extracts the main salient subject or subjects in each frame, the same way it does for images. Best results come from a clearly separated subject, steady lighting and footage at or below 1080p. Known limitations:

- **Crowds and partial subjects.** Crowds, people only partially visible at the frame edge, and small background objects may be dropped from the matte.
- **Overlays.** Burned-in captions, logos and watermarks are often kept as foreground. Strip overlays before processing and add them back afterwards.
- **Touching objects.** Objects that touch or overlap the subject (poles, laptop edges, hand-held items) can be included in some frames and not others.
- **Black or white frames.** Fully black or fully white frames, such as fade-ins and fade-outs, produce an empty matte by design.
- **Fine edges and motion.** Hair and fur edges are soft. The temporal stabiliser reduces edge flicker on static parts of the frame but does not eliminate it on fast motion.

### Credits

| Source frame rate | Cost |
|---|---|
| Up to 30 fps | 5 credits per second of source video, rounded up to the whole second |
| Above 30 fps | 10 credits per second of source video, rounded up to the whole second |

The credit charge does not depend on `format`, `channels`, `size` or resolution. A 12.4 second clip at 29.97 fps is billed as 13 seconds, so 65 credits. One credit equals one image or 0.2 seconds of video.

Credits are charged when the job is accepted, and the `202` response tells you the exact amount in `credits`. If the job fails, the credits are refunded automatically. Rejected submissions (`4xx` errors) are never billed. Polling the job and downloading the result are free.

### Video examples

Submit a clip with `file`, poll the job every few seconds, and download the transparent WebM from `result_url`:

<CodeGroup>

```bash cURL
# 1. Submit the video (returns the job as JSON; note the "id")
curl -X POST https://api.poof.bg/v1/remove \
  -H "x-api-key: YOUR_API_KEY" \
  -F "file=@clip.mp4" \
  -F "format=webm"

# 2. Poll the job every few seconds until "status" is "completed" (or "failed")
curl https://api.poof.bg/v1/jobs/job_8f3a1c2e9b7d4a10 \
  -H "x-api-key: YOUR_API_KEY"

# 3. Download the result from "result_url" (a public CDN link, no API key needed)
curl -o clip-nobg.webm \
  https://cdn.poof.bg/1d/jobs/job_8f3a1c2e9b7d4a10/result.webm
```

```python Python
import time
import requests

API = "https://api.poof.bg/v1"
headers = {"x-api-key": "YOUR_API_KEY"}

# 1. Submit the video
with open("clip.mp4", "rb") as f:
    r = requests.post(
        f"{API}/remove",
        headers=headers,
        files={"file": f},
        data={"format": "webm"},
    )
r.raise_for_status()
job = r.json()
print(f"Job {job['id']}: {job['duration_seconds']} s, {job['credits']} credits")

# 2. Poll every few seconds until the job finishes
while job["status"] not in ("completed", "failed"):
    time.sleep(3)
    r = requests.get(f"{API}/jobs/{job['id']}", headers=headers)
    r.raise_for_status()
    job = r.json()
    print(f"{job['status']} {job['progress']:.0%}")

if job["status"] == "failed":
    raise RuntimeError(f"{job['error']['code']}: {job['error']['message']}")

# 3. Download the result (a public CDN link, no API key needed)
with requests.get(job["result_url"], stream=True) as r:
    r.raise_for_status()
    with open("clip-nobg.webm", "wb") as out:
        for chunk in r.iter_content(chunk_size=1024 * 1024):
            out.write(chunk)
```

```typescript TypeScript
import fs from 'node:fs';
import { readFile } from 'node:fs/promises';
import { Readable } from 'node:stream';
import { pipeline } from 'node:stream/promises';
import type { ReadableStream as NodeReadableStream } from 'node:stream/web';

const API = 'https://api.poof.bg/v1';
const headers = { 'x-api-key': 'YOUR_API_KEY' };

// 1. Submit the video
const form = new FormData();
form.append('file', new Blob([await readFile('clip.mp4')]), 'clip.mp4');
form.append('format', 'webm');

const submit = await fetch(`${API}/remove`, { method: 'POST', headers, body: form });
if (!submit.ok) throw new Error(await submit.text());
let job = await submit.json();
console.log(`Job ${job.id}: ${job.duration_seconds} s, ${job.credits} credits`);

// 2. Poll every few seconds until the job finishes
while (job.status !== 'completed' && job.status !== 'failed') {
  await new Promise((r) => setTimeout(r, 3000));
  const res = await fetch(`${API}/jobs/${job.id}`, { headers });
  if (!res.ok) throw new Error(await res.text());
  job = await res.json();
  console.log(job.status, `${Math.round(job.progress * 100)}%`);
}
if (job.status === 'failed') throw new Error(`${job.error.code}: ${job.error.message}`);

// 3. Stream the result to disk (a public CDN link, no API key needed)
const result = await fetch(job.result_url);
if (!result.ok) throw new Error(await result.text());
await pipeline(
  Readable.fromWeb(result.body as NodeReadableStream),
  fs.createWriteStream('clip-nobg.webm')
);
```

</CodeGroup>

## Error Responses

All errors return a flat JSON body (`{ "code", "message", "details"?, "request_id", "doc_url" }`) and carry an `X-Request-ID` header. Failed and rejected requests are not billed.

| Status | Code | Description |
|--------|------|-------------|
| 400 | `validation_error` | Invalid parameter value (for example a `format` from the wrong media family, or an image-only parameter sent with a video), or non-multipart body |
| 400 | `missing_image` | No `file`, `url` or legacy `image_*` input provided |
| 400 / 413 | `image_too_large` | Image exceeds the 20 MB limit (413 when rejected by the processing service) |
| 400 | `video_too_long` | Video is longer than 5 minutes |
| 401 | `authentication_error` | `x-api-key` missing or not recognised |
| 402 | `payment_required` | Monthly credits used up, or not enough left to cover the whole video |
| 403 | `permission_denied` | Endpoint or feature not included in your plan |
| 413 | `video_too_large` | Video upload exceeds 100 MB, or the file at `url` exceeds 500 MB |
| 422 | `invalid_image` | File could not be decoded as PNG, JPEG or WebP |
| 422 | `invalid_video` | File was detected as a video but could not be decoded |
| 429 | `rate_limit_exceeded` | Per-plan requests-per-minute limit or global per-IP limit hit |
| 500 | `processing_failed` | The model or encoder failed on this image |
| 500 | `internal_server_error` | Unexpected server error, retry later |
| 502 / 503 / 504 | `upstream_error` | Processing service unreachable, unavailable, or timed out; retry with backoff |

A video that is accepted but fails during processing does not produce an error response: the job ends with `status: "failed"` and an `error` object, and its credits are refunded automatically. See [Get Job](/api-reference/jobs).

See [API Error Codes](/errors/list) for detailed troubleshooting.
